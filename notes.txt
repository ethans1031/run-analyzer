Controllers: receive request, define endpoints
Services: business logic or functionality 
Models/Entities: Data classes with attributes

Services classes are static(?) so for example public static class PizzaService

Methods that list/add/delete/update are defined in your service and then called in your controller. So the PizzaService would have a GetAll and that would be called in the controller

Task<T> is like async await in javascript

"dotnet ef migrations add ChangeDescription" -> part of ef core, used to change db schema, generates a migrations file that you can look attributes

"dotnet ef database update" apply changes from above
